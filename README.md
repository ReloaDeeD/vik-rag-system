# RAG-система для семантического поиска по корпоративным документам

Программный модуль интеллектуального поиска, построенный на архитектуре **Retrieval-Augmented Generation (RAG)**. Система принимает вопросы на естественном языке по внутренней документации компании и возвращает точные ответы со ссылками на первоисточники — без передачи данных во внешние сервисы.

## Решаемая проблема

В компаниях знания разрознены по десяткам документов: регламенты, инструкции, wiki, технические описания. Классический поиск по ключевым словам не понимает смысл вопроса и выдаёт нерелевантные результаты при перефразировании. Публичные нейросети (ChatGPT и аналоги) неприменимы из-за рисков утечки коммерческой тайны.

## Возможности

- 📚 Загрузка документов в форматах TXT, MD (PDF и DOCX — в разработке)
- 🔍 Семантический поиск по смыслу с пороговым отсечением нерелевантных ответов
- 📏 Вывод расстояний для оценки уверенности системы
- 📎 Указание источника в ответе: имя файла и номер фрагмента
- 🔒 Локальное развёртывание — данные не покидают периметр предприятия
- 🌐 Поддержка русского языка

## Технологический стек

- **Python 3.14** — основной язык
- **ChromaDB** — векторная база данных (коллекция `corp_docs`)
- **Sentence-Transformers** — модель `paraphrase-multilingual-MiniLM-L12-v2` для эмбеддингов
- **SQLite** — реляционная БД метаданных и журнала запросов (таблицы `documents`, `chunks`, `query_log`)

## Установка и запуск

### Требования
- Python 3.11 или выше
- Git

### Шаги
```bash
# 1. Клонировать репозиторий
git clone https://github.com/ReloaDeeD/vik-rag-system.git
cd vik-rag-system

# 2. Создать и активировать виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\Activate.ps1
# Linux/macOS:
source .venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать БД метаданных
python init_db.py

# 5. Проиндексировать документы
python indexer.py docs

# 6. Запустить поиск
python search_with_sources.py "ваш вопрос"
```

Первый запуск скачает модель эмбеддингов (~500 МБ), последующие запуски быстрые.

## Принятые решения

- Чанкинг: по абзацам (пустым строкам), дочитывание символами при длине > 600.
- Порог отсечения нерелевантных ответов: 0.7. Подобран эмпирически: расстояния ответов ~0.4–0.5, ловушек ~0.75+ (замеры от 09.10.2026). При расширении корпуса порог перепроверять.
- Обоснования и схема компонентов — в [architecture/architecture.md](architecture/architecture.md).

## Статус разработки

**Этап 1 (фундамент и прототип) — в процессе завершения(прототип):**
- Анализ предметной области и архитектур RAG
- Проектирование и реализация БД метаданных (SQLite) и векторного хранилища (ChromaDB)
- Единый модуль индексации (SQL + ChromaDB под общими id)
- Проиндексированный тестовый корпус (3 документа, 15 чанков)
- Документированная архитектура

**Этап 2 (впереди):**
- Интеграция LLM (Ollama) и генерация ответов по контексту
- Гибридный поиск (векторный + BM25) и re-ranking
- Тестовый датасет и метрики RAGAS
- Веб-интерфейс (Streamlit) и Docker-упаковка
