# Архитектура RAG-системы

Документ описывает текущую архитектуру системы (этап 1) и планируемые компоненты (этап 2).
Ведётся параллельно с кодом: при изменении компонентов обновляется и этот файл.

## 1. Назначение

Система выполняет семантический поиск по корпусу корпоративных документов:
на вопрос пользователя возвращает релевантные фрагменты с указанием источника
(файл, номер фрагмента) и оценкой уверенности (расстояние). Генерация ответов
средствами LLM будет добавлена на этапе 2.

## 2. Состав компонентов

| Компонент | Файл / расположение | Ответственность |
|---|---|---|
| Парсер документов | `document_parser.py` | Извлечение текста из PDF, DOCX, TXT, MD. Формирование блоков с локаторами (страница/абзац). |
| Модуль индексации | `indexer.py` | Умный чанкинг, запись в SQLite и ChromaDB под общими id. |
| Хранилище метаданных | `data/metadata.db` (SQLite) | Таблицы `documents`, `chunks` (с локаторами), `query_log`. |
| Векторное хранилище | `data/chroma` (ChromaDB) | Векторы и тексты чанков, поиск ближайших по смыслу. |
| Модуль поиска | `search_engine.py` | Гибридный поиск (BM25 + Vector + RRF) и Cross-Encoder реранкинг. |
| Модуль генерации | `generate_answer.py` | Обращение к локальной LLM (Ollama) для формирования ответа. |
| Оценка качества | `evaluate.py` | Прогон тестового датасета (40 вопросов) по разным режимам поиска. |
| Веб-интерфейс | `app.py` (Streamlit) | UI для загрузки документов, вопросов и просмотра ответов со ссылками. |

## 3. Потоки данных

### Индексация
1. `document_parser.py` читает файл (PDF/DOCX/TXT/MD) и извлекает блоки текста с привязкой к странице (PDF) или абзацу (DOCX).
2. `indexer.py` считает SHA-256 отпечаток файла: если файл не менялся — пропуск; если изменился — удаление старой версии из обеих баз.
3. Выполняется **Умный чанкинг**: короткие абзацы склеиваются (до ~300 символов), длинные режутся по границам предложений (до ~800 символов).
4. Чанки вставляются в SQLite (`chunks`), получают id и сохраняют `locator` (например, "page 1" или "абзац 1 – абзац 3").
5. Те же чанки уходят в ChromaDB под id `chunk_<id из SQLite>` с метаданными (`document_id`, `chunk_index`, `title`, `locator`).

### Поиск и Генерация
1. Вопрос векторизуется моделью `paraphrase-multilingual-MiniLM-L12-v2`.
2. **Гибридный поиск**: ChromaDB возвращает топ-N векторов, `rank-bm25` возвращает топ-N по ключевым словам.
3. Результаты объединяются алгоритмом **RRF (Reciprocal Rank Fusion)**.
4. **Переранжирование (Re-ranking)**: объединенный список прогоняется через Cross-Encoder `BAAI/bge-reranker-base`, который оставляет топ-7 наиболее релевантных фрагментов.
5. Найденные фрагменты вместе с локаторами (например, `vacation.md, абзац 4`) передаются в локальную LLM (`qwen2.5:3b`).
6. LLM генерирует ответ, опираясь только на контекст, и указывает ссылки на источники. Вопрос и ответ логируются в `query_log`.

## 4. Ключевые проектные решения и их обоснование

1. **Умный чанкинг (Smart Chunking).**
   Обоснование: простое деление по абзацам рвёт смысл (если абзац короткий) или обрезает предложения. Склейка коротких блоков и нарезка по предложениям дают LLM полноценный контекст.
2. **Связка id SQLite ↔ ChromaDB с полем `locator`.**
   Обоснование: позволяет в результатах поиска называть точный источник (файл, страницу или абзац), что критично для доверия к RAG-системе.
3. **Использование Cross-Encoder (`BAAI/bge-reranker-base`) вместо LLM для реранкинга.**
   Обоснование: эксперименты показали, что маленькие LLM (3B) плохо справляются с задачей сортировки списков. Cross-Encoder работает в разы быстрее, локально и повышает `Context Precision` до 0.825.
4. **Гибридный поиск (BM25 + Векторы).**
   Обоснование: Векторы лучше понимают смысл (перефразирования), а BM25 — точные термины, артикулы и числа. RRF объединяет их сильные стороны.

## 5. Ограничения и направления развития

- **Docker и FastAPI**: отложены (система работает в виде локального Streamlit-приложения).
- **OCR**: сканированные PDF (без текстового слоя) не обрабатываются.
- **LLM (qwen2.5:3b)**: может давать ложные отказы на сложных вопросах. Замена на модель 7B+ улучшит качество.
